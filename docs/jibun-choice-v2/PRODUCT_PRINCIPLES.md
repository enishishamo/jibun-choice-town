# PRODUCT PRINCIPLES — JIBUN CHOICE Ver.2

制定: 2026-09-20（Human Decision）。状態ラベルは [README.md](README.md) 参照。

## 1. Mission（LOCKED・変更不可）

> 生まれた環境によらず、子どもが自分で将来を選べる社会をつくる。

Ver.2 は Mission を変更しない。**Mission への届け方**を変更する。

## 2. 絶対に変えないこと（LOCKED）

- 「将来何になりたい？」から始めない
- 知らなかった社会との**偶然の出会い**をつくる
- 職業名より先に、その仕事の**「行為」**を体験する
- 「あなたにはこの仕事が向いています」という**適性判定をしない**
- 好きなものが最初から分かっている前提にしない

（`factory/rules/principles.md` の「職業名から始めない」「適職診断禁止」と同一線上。）

## 3. Ver.2 の基本思想 — PLAY FIRST（LOCKED）

| 旧（Ver.1） | 新（Ver.2） |
|---|---|
| 説明を読む → 理解する → 操作する | **触る → 何か起こる → もう一度触る → 遊びながら理解する** |
| 仕事を説明するゲーム | その仕事で**実際に行っている行為**そのものをゲームにする |

- 職業名は基本的に**後出し**。遊ぶ前に「これは○○という仕事です」と説明しない。
- 「仕事を知ってもらうためにゲームを使う」ではなく
  「ゲームとして遊んでいたら、知らない仕事・社会に出会っていた」。

## 4. Ver.2 のゲームループ（LOCKED・core gameplay loop）

```
相棒と探検する
 ↓ 気になる巨大オブジェを見つける
 ↓ 触る
 ↓ パカッと開く
 ↓ そのモノの裏側にある社会が現れる
 ↓ 気になる場所を触る
 ↓ 職業名の説明ではなく、仕事の「行為」がゲームとして始まる
 ↓ 遊ぶ / 試す / 解決する
 ↓ あとから「いまやっていたのは○○という仕事のひとつ」と知る
 ↓ WORLD MAP に戻る
 ↓ その場所のアイコンが点灯
 ↓ 関係する道が光ってつながる
 ↓ 体験由来のアイテムを獲得
 ↓ 相棒に身につけられる
 ↓ 「ぼうけんノート」に記録
 ↓ 次の世界・次の行為を探す
```

要約: **🔍 探す → パカッ → 遊ぶ → 知る → ❤️「好きかも」を見つける → 持ち帰る → また探す**

Ver.1 との対応: Ver.1 の Q1 シェル（intro → game → discovery / Job Reveal / 好きの種）は
「遊ぶ → 知る → ❤️」の部分に相当する。「探す / パカッ / 点灯 / 道が光る / アイテム / ノート」は
Ver.2 で新設される（→ [WORLD_DESIGN.md](WORLD_DESIGN.md), [GAME_DESIGN_RULES.md](GAME_DESIGN_RULES.md)）。

## 5. UI / TEXT RULE（LOCKED・非常に重要）

**文章を短くすることが目的ではない。**
原則: **「絵・動き・反応で伝えられるなら、文字を書かない」**

- 子どもは文章を読まずに直感的にタップする。その行動を**前提**に設計する。
- **説明画面を先に置かない。**
- 優先順位: 触りたくなる → 触る → 反応する → 意味が分かる
- 説明文・「！」マーク・進捗バー等は「あると便利」ではなく、
  PLAY FIRST に照らして**個別に必要性を判断**して初めて置く。

Ver.1 の既知の反例（`audits/` 参照）: Q1 intro の mission 文、開閉式 InfoCards の中にしか
書かれていない判定条件、「読む→3択」だけのステップ。Ver.2 では同型を作らない。

- 表示する文言と文字量は **Design Owner（GPT）が決める**。Claude Code は tutorial copy・
  success message・helper text 等を独自に追加しない（[DESIGN_OWNERSHIP.md](DESIGN_OWNERSHIP.md) §2）。
- PLAY 画面では背景装飾より「今触ってほしいものが最も触れそうに見える」ことを優先する
  （[VISUAL_TONE.md](VISUAL_TONE.md) §6）。

## 6. Ver.1 から引き継ぐ設計原則

`factory/rules/principles.md` の以下は Ver.2 でもそのまま BLOCKER:

- 説明→次へ→説明→クリア（読むだけ進行）
- 明らかな正解だけの 2 択
- C（仕事特有の情報・道具）を使わなくても攻略できる
- 操作結果と無関係に固定クリア
- 職業名先出し / 適職診断
- 失敗時に即答を文章で教える
- 実務主体を推測で断定（不明なら fact-check フラグ）

Ver.2 で**追加**される原則は [GAME_DESIGN_RULES.md](GAME_DESIGN_RULES.md) を参照。

## 7. Product Identity Gate との関係

相棒キャラクター・ゲームループ・アイテム・ぼうけんノートは
`factory/rules/product-identity-gate.md` の対象であり、本仕様書群で **Human が決定した範囲**のみ
実装してよい。仕様書に **OPEN** と書かれた点（形態の細部、獲得ルールの数値、分類軸 等）は
引き続き Human Decision が必要で、AI が埋めてはならない。
