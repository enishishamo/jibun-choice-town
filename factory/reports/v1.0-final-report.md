## 3. 新ゲート統合（ユーザー指示・Stage 8中に追加）

### 3a. Series Style Gate（Art）
- 固定reference set（既存良好7画像）をQA・生成の両方に**実画像**添付。SERIES_STYLE_MATCH / CHARACTER_SERIES_MATCH **<80でFAIL**（総合点による救済禁止）。
- Stage 6-8 生成画像9点を再監査 → 全PASS。ユーザーがズレを指摘した char-haru はborderline（83/82）だったため**再生成 → SSM92/CSM94**（目・肌・髪・服が既存シリーズの粘土質感に一致）。
- repair は critic の series_diffs を verbatim 注入（曖昧語禁止）。contact sheet 自動生成。

### 3b. Gameplay Experience / Game Reference Gate
- Critic v3 軸を規約化: WORLD_FEEDBACK_QUALITY / TEXT_ONLY_CONSEQUENCE / HINT_LEAKAGE（段階的hint）/ VISUAL_GAMEPLAY_LEGIBILITY / GAMEPLAY_REFERENCE（skin copy禁止・空で完成禁止）/ TRACEABILITY / GAME-LIKENESS質問。
- 新規8ゲームの reference 追跡を記録（factory/taxonomy/gameplay-references.json — Papers Please / Overcooked / Mini Metro / FTL / Frostpunk 等の**原理**を職業難しさへ翻訳した系譜）。レビュアー検証で8/8 principle-level・skin copyなし。
- Codex adversarial レビュー（フル3周＋焦点3周）で repair：
  - 「失敗画面でも世界状態を消さない」を統一原則化（pit最終盤面+温度計 / gas計器盤 / checkup診断盤+観察窓 / baby曲線+判断アイコン+❗ / debut失敗ヤード / feedトレイ / curb街路ストリップ）
  - curb_check を「文章で答え合わせ」から「荷台/残置/連絡待ちへ袋が移動し、誤判定は❗が残り、危険物積載は🔥で日が終わる」世界へ再実装
  - refusal文から規則開示を全廃（園長は首を横にふるだけ。規則はCカードが担う）・段階的ヒント（先輩は黙って指さす/データを並べ直す）
  - 最終確認: フル3周＋焦点3周（最後はdebut単独）の結果、**8/8ゲームがバー通過**（WFQ/VGL≥70・TOC=false・HL=false）：
    curb 80/82・pit 88/90・gas 74/76・landfill 86/87・feed 80/84（3周目）、baby 73/76・checkup 82/84（焦点1）、debut 80/76 **PASS 78**（debut単独最終・B/H=0）。
    GAMEPLAY_REFERENCE は 8/8 が principle-level と独立検証（skin copyなし）
- 既存39ゲームは新axesでCodexスキャンし **28件をrepair backlogへ**（factory/state/experience-backlog.json。worst: LifePlan / NurseObserve / DelayRecover / LoanScreen / SceneAudit）。

### 3c. Asset Presentation Gate（in-context）
- **asset単体QA ≠ 表示QA** を分離。present-shots.mjs（puppeteer-core＋手元Chrome、全世界汎用walker＋完走アサーション＋consoleエラーでexit 1）で実スクショ（mobile+desktop）→ art-qa `presentation` モード（APQ<80 / BADGE_COLLISION でFAIL）。
- 12画面を監査 → 5画面FAILを修理（町マップのバルーンedge-clamp[全世界共通の機械修正]・zoo areaラベルstagger・debutヤード視認性・ui-*.png 5点の背景透過化・waste mapPos）→ **全12画面PASS**（town-map 90 / zoo-wrapup 92 / shop-haru 96 等）。
- 共有UIの系統的指摘7件は presentation-backlog.json（バルーン衝突エンジン・callout共通コンポーネント・絵文字アイコン統一など）。

## 4. §16 Factory 自己批判（Codex adversarial・3周）

iter1 **FAIL 22**（BLOCKER 4）→ 機械修理 → iter2 **FAIL 58**（BLOCKER 0）→ 機械修理 → iter3 FAIL 42（新規指摘へ深化）→ さらに修理し、**max-iterations 停止**（ループ規約どおり明示停止・残項目は下記「既知の制約」に開示）。

主な機械修理:
- **コスト境界**: 全codex transport（review/task/art-qa/art-provider）で API-key環境変数を除去し、さらに `codex login status` が **ChatGPT OAuth 以外なら機械拒否**（API-keyログインセッションの排除）
- **レビュアー独立**: codex-review が producer供給promptの前に**不変のINDEPENDENCE前文**を注入（PASS前提・重大度上限・自己評価の採用を上書き禁止）
- **観測可能性**: art-qa / art-provider / codex-review の全呼び出しを routing-log.jsonl へ記録
- **完了の機械検証**: validate-pipeline.mjs（自己申告では完了にならない。binding review JSON 再読込、gameplay QA 実実行、presentation監査必須、world別 reference 必須、run帰属はpath-anchored）
- **正直化**: reuse資産は `reused_existing`（qa_passed 偽装廃止）、provider probe は14日で失効（fail-closed→human_boundary）、reference set欠落はQA/生成ともfail-closed、pipeline.json整合修正、stale文言の更新
- **規約の正本化**: バインディングゲート＝実装二軸レビュー（B/H=0）、オーケストレータ＝Claudeセッション（機械ゲート＋証跡付きの設計として明文化）、人間介入の定義（世界コンテンツ vs 工場レベル較正）

## 9. 既知の制約（正直な開示）

1. **レビュアー分散**: Codex レビューはイテレーション間でスコアが振れる（例: gas_watch 74→52→74）。バインディング判定は「点数」でなく「B/H=0＋閾値」で行い、max-iterations で明示停止する規約で吸収している。
2. **§16 残項目**: validate-pipeline はbuild/browser QAまでは実行しない（gameplay QAは実行する）・metricsの一部はオーケストレータ集計（source_note開示）・deep flow bot は per-world 資産（gameplay-qa-<world>.mjs と同じ設計判断）・routing-log は書込失敗を握りつぶす（QAを壊さない選択）。
3. **既存アプリの backlog**: 体験ゲート28件（既存39ゲーム）・presentation系統7件（共有UI）。v1.0 の対象は Stage 7/8 新世界＋新ゲートの工場統合であり、既存全面改修は含まない（ユーザー指示どおり）。
4. **人間介入の定義**: 世界コンテンツへの介入は0。ただしユーザーによる**工場レベル**の較正裁定（C単独確定のみ問題）と3ゲート追加指示は本セッション中に受領し、工場仕様として統合した（世界の human_interventions には数えず、ここに開示する）。
5. 実子ども検証は未実施（§7）。
