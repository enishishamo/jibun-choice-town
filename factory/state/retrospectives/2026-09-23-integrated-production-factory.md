# Retrospective — 統合Factory（調査→ゲーム設計→Design引き渡し）と 初パイロット「はこぶ」

2026-09-23。短く、繰り返す項目だけを残す。

## 1. 新設しなかったことが一番大きい判断

監査で分かったのは、前工程のパイプラインが**既に存在していた**ということだった。
`q1-pipeline.mjs` + `q1-factory-schema.mjs` は、成果物のversion管理・上流追跡・
transitive STALE・失敗時の差し戻し先・有限の予算まで実装済みで、11本の Q1
パイプラインがこれで動いた記録が残っていた。Ver.2 がこれを使わず素の markdown に
戻していただけだった。

もし監査を省いて「前工程を作れ」と言われたとおりに作っていたら、
**3つ目のプロジェクト形式**が生まれていた（`pipeline.json` / `q1-pipeline.json` に
続く3つ目）。監査それ自体が最大の成果物だった回。

促成のルール: **「無い」と言われたものを作る前に、コードを読んで本当に無いことを
確かめる。** ドキュメントが古いだけ、という可能性が常にある。

## 2. FACT GATE は初適用で仕事をした

「はこぶ」の決定マップ12行のうち2行を機械的に落とし、落ちた1行が
**「配送計画の策定」**——物流と聞いて誰もが最初に思いつく経路ゲームの素だった。

落ちた理由は事実である。配送ルートと各校の時刻は運転手が決めていない。
発注者が契約時に別紙として固定しており、3自治体の仕様書で一致している。
運転手の当日の判断は「異変に気づいてセンターへ連絡し指示を受ける」。

ゲートが人間の宣言だったら、この案は通っていた。
**ステレオタイプは「気をつける」では止まらない。機械が止める必要がある。**

## 3. しかしゲートには穴があり、それは1回目の実走で露出した

FACT GATE は決定マップの**行**を検証する。ゲーム案がその行に**立脚しているか**は
誰も検証していなかった。両者が別スコープで検証されていたための構造的な穴。

結果、設計者（私）が「配送員が、あと1品待つか・不完全なコンテナを閉めて送り出すかを
決める」という、どの資料にも存在しない判断を発明した案が、独立 critic まで到達した。

修正: `conceptRowTraceProblems`。各案は `rows[N]` 形式で根拠行を名指しし、その行が
実在しゲートを通っていることを submit 時点で検査する。self-test I で、却下済み行の
上に立つ案と根拠を名指ししない案の両方が落ちることを確認した。

促成のルール: **ゲートを足したら、その出力を使う側も同じゲートに繋ぐ。**
「行を検証した」と「案がその行の上にある」は別のことで、後者を検査しないなら
前者の検査は設計に対して無力である。

## 4. 2ラウンドとも採択 NONE。そしてそれは失敗ではない

| round | 設計者 | 判定 | 採択 |
|---|---|---|---|
| r1 | claude-code-game-designer | FAIL 43（CA 42 / GQ 45）blocker 4 | NONE |
| r2 | claude-code-game-designer-2（交代） | FAIL 38（CA 41 / GQ 36）blocker 5 | NONE |

r2 の blocker 5件はすべて同じ形をしていた: **勝敗を支える中核ルールが、確認されて
いない事実の発明である。** 「確認には一律t時間」「センターは最初の連絡だけで資源を
不可逆投入する」「運搬車台数×品目数＝必要数」「過剰分離にコストがある」——
いずれも work_research の unconfirmed に該当する。創作規則を外すと、固定戦略を
負かす機構が消える。

つまりこれは**設計の失敗ではなく事実の不足**である。差し戻し先は GAME_CONCEPTS
ではなく WORK_RESEARCH。`reject-concepts` は予算を消費しないので、正しい回数だけ
戻れる。

促成のルール: **blocker が全部「根拠がない」の形をしていたら、それは設計者の
力不足ではない。研究へ戻す合図である。** 設計者を替えても直らない。

## 5. 設計者の交代は効いた

r1 の中心的な誤りは「誰もしていない判断の発明」だった。同じ人格に直させると、
必ず言い訳と部分的な手当てになる。別コンテキストの設計者に交代させたところ、
r2 の案は r1 の4 blocker のうち3つを構造的に起こりえない形にしてきた
（検食の時系列誤りは critic 自身が LOW で「実質的に修正されている」と認めた）。

同時に、交代した設計者は **A と C を「作らない」と自分から明記した**。
「実務の真実（ほとんどの日は何も足りない）とゲームの要請（毎回判断が起きる）が
正面衝突しており、表現では解けない」という理由づけは、私には書けなかったものだ。

促成のルール: **作った人に直させない。** producer ≠ reviewer は既に機械強制されて
いるが、**producer ≠ next producer** は規律として持つ価値がある。

## 6. critic も間違える。機械で検算する

r2 の HIGH に「『通過行は三つだけ』という全数主張が偽」という指摘があり、
根拠として「FACT GATE は row[0] だけを落として10行を通した」と書かれていた。

機械的に検算すると、ゲートは **rows[0] と rows[3] の2行**を落としており、
配送業務従事者が actor で通過したのは rows[4]/[5]/[9] の3つ。設計者の主張が
正しく、critic の反証が誤読だった。

ただし critic の**下敷きにあった懸念は正しい**: rows[3]（出発前点検と異常時の
予備車要請）は distortion_risk LOW でありながら、私が gameability LOW と
付けたことだけで落ちている。これは事実ではなく判断である。

促成のルール: **critic の指摘も、機械で確かめられるものは確かめる。**
そして自分のゲートに入れた主観的な値（gameability）は、事実と同じ棚に置かない。

## 7. repo が知らなかったこと

参照調査で、この repo に**「いまの小学生が実際に遊んでいるゲーム」の分析が1件も
無い**ことが分かった。既存15本はすべて大人向けPC/据置の名作（Papers Please、
Overcooked、Tetris…）で、認知負荷・セッション長・最初の30秒がまったく別の問題。

ゲムトレ2025（小学生324名・うち小4〜6が170名）で実証を取り、6本を
`first_30_seconds` つきで追加した。意外だった補正: **この層はスマホ中心ではなく
Switch 優位**（Minecraft 28.4% / スプラトゥーン 16.9% / あつ森 12.0%）。
本プロダクトはスマホなので、Switch の文法を指1本へ翻訳する作業が要る。

## 7.5. 再定義の後（r3）— 窓を広げても、同じ根で止まった

Human Decision がスポットを再定義し、ゲーム化対象を裁量的 decision に
限定しないことにした。実装して頭から回し直した。**再定義は効いた**:

| 指標 | 旧（decision 中心） | 新（action） |
|---|---|---|
| ゲート通過行 | 10 | 19 |
| うち DECISION | 10 | 1 |
| critic スコア | 43 → 38 | 51 |
| CA / GQ | 42/45 → 41/36 | 57/56 |

18行は旧定義では見えていなかった。両軸とも50台まで来た。それでも
床の60には届かず、3ラウンド目も採択 NONE。

**3回とも blocker の形は同じだった。**

| round | 発明された規則 |
|---|---|
| r1 | 配送員が出発の可否を決める |
| r2 | 確認に一律 t 時間／センターは最初の連絡だけで不可逆投入 |
| r3 | 直送便の到着順と各学級の開始間隔／一人分の適量の閾値 |

設計者は3人とも別人格で、毎回 critic の指摘を読んで入った。それでも
同じ場所で詰まった。したがってこれは個人の問題ではない。

**根は、この職業の運用パラメータが公開されていないことにある。**
配送計画の別紙、報告項目、センターの対処手順、記録簿の欄名、一人分の適量、
別保管の容量上限——8文書・7自治体を当たって一つも出てこなかった。
そして**ゲームの緊張は、普通そこから来る**。締切・所要時間・容量・閾値。
それが無い題材では、緊張を作ろうとするたびに発明になる。

促成する規律: **運用パラメータが非公開の職業では、時間・順序・閾値に
依存しない設計しか許されない。** 空間的な完全性（全部埋まったか）、
実在する文書との突合、対称な二値応答——これらはパラメータを要求しない。
逆に「何分以内」「何個まで」「どれくらいが適量」を要求する設計は、
その職業の資料を先に確認してから着手する。

**我々自身の記録の不正確さも1件見つかった。** RECORDING を見送った理由を
rows[13]（欄名未確認）と rows[20]（学級×品目・計量・記録表がいずれも明文）で
一括して「事実が足りない」と書いた。rows[20] は発明が要らないので、
本当の理由は「ゲームとして弱い」である。critic に指摘されて訂正した。
**区別を曖昧にしたまま「事実が足りない」と書くと、後から事実を足そうと
する人が無駄足を踏む。** 見送りの理由は、事実不足とゲーム性不足を必ず分ける。
