# §11 Map Architecture — Claude × Codex 独立評価と決定（2026-09-03）

## 独立評価（互いの結論は非共有で実施）
- **Claude**（map-options-claude.md）: D（中心街から連続拡張・カメラ移動）を基幹に、
  C（増殖のワクワク）とF（靄と開示）を吸収した hybrid。
- **Codex**（map-eval-codex.json）: 独自案 **G「Living Event Atlas」** —
  安定した地域俯瞰（5-8の記憶しやすい地区）＋常設バルーンでなく**動くイベントシグナル**
  ＋地区close-up scene＋靄/シルエットによる新地区予告。B+D+F要素のhybrid。
  Dにも exploration 9 / discovery 9 の高評価。Dの弱点として「1軸パンの総延長が50worldで限界」を指摘。
- **Codex map research**（20タイトル）主要原則: 「50を一枚に並べない（5-7地区×5-10地点の二階層）」
  「地区は文字なしで区別できる巨大ランドマークを持つ」「NEWバッジでなく 工事→煙→灯り→人だかり→新しい道 の順で世界内に出現」
  「未開放は灰色カードでなく“霧の向こうのシルエット”」「成果が広場へ戻る」。

## 決定: 「生きた町のアトラス」= G(Codex) × D(Claude) 統合
1. **Level 1 = 地域マップ（ホーム）**: 一枚の連続した地域キャンバス（SVG地形＋地区ランドマーク）。
   中心は現在の町（town-hero継続使用）。パン可能（モバイル両軸・境界つき）＋地区チップでジャンプ。
   「いま何かおきている」シグナル（煙/光/人だかり/ゆれ）を**最大3-5個だけ**前面化（NEWの洪水を構造的に防止）。
   未開示地区は靄＋シルエット＋気配。
2. **Level 2 = 地区scene**: 地区タップで**カメラが寄るズーム演出**（CSS transform、
   画面カットでなく連続感を維持=Claude D要素）→ 地区の景観にworld hotspot群。
   既存worldのsceneMap/AreaScreen以降は不変。
3. **World状態**: UNSEEN(靄)/DISCOVERED(シルエット→建物出現)/VISITED/IN_PROGRESS(⚒)/
   COMPLETED(旗+小変化)/UPDATED(煙・人だかり)。地図表現が状態で変わる。完了圧はかけない
   （COMPLETEDは静かな変化のみ、達成率バー等は出さない）。
4. **拡張規則**: 1地区あたりworld 3-8。超えたら新地区が「橋の建設→開通」の演出で増える
   （増えること自体がワクワク=C要素）。50world=7-8地区で成立。
5. **配置**: generic layout system（district内slot自動割付・衝突回避）。mapPos%手打ちの増殖を止める。

## 選定理由（実装の容易さでは選んでいない）
両独立評価が一致した3点を全て満たす唯一の形だから:
(a) event-first哲学の維持（シグナル=出来事が呼ぶ。職業分類は前面に出ない）
(b) 9→14→50のスケール（二階層+地区増殖）
(c) 「世界の中を見ている」感覚（連続キャンバス+ズーム演出、画面カット排除）。

## 最大リスクと緩和（両評価の指摘を統合）
- 「古いworldが消えた/進捗が失われた」と誤解させない（Codex）→ シグナルは減衰しても
  建物・旗・住民の変化は**恒久**。地区チップに未完了の気配を小さく残す。
- パン迷子（Claude）→ 地区チップ常設・現在地インジケータ・「まちへもどる」1タップ。
- 地区内密度 → slot上限とauto新地区。
