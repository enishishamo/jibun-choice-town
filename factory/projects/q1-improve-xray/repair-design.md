# XrayGame 小規模改修設計（repair design）

監査（audit.md）の FAIL を受けた改修案。世界再設計はせず、既存の演出資産
（BodyInsideView の透過演出・クレイ調 SVG・E 画面）を維持したまま、
技師の中核ループを小学生向け粒度で追加する。

## 追加する A→B→C⇄D→E 要素

- **C（職業固有の情報）**: 医師の「さつえい依頼票」
  - みたい場所: むね（肺）
  - 大事なこと: 「息を止めた瞬間に撮る」（動くとブレる）
  - 部位の正解をノートで教える現行実装を廃止し、依頼票を読む→部位を選ぶ形へ
- **D（C を使った操作・試行錯誤）**: 呼吸インジケータを見てシャッターを切る
  - 患者の呼吸が「すって…はいて…すって…【とまる】」とサイクル表示される
  - 【とまる】のタイミングで撮ればくっきり、動いている間に撮るとブレ画像
- **失敗と再試行**: ブレ画像は「これでは医師に届けられない」→ 撮り直し
- **判断**: 撮れた画像を自分で「とどける / とりなおす」判定する
  - ブレ画像を届けようとすると差し戻し（先輩技師の一言）
  - くっきり画像なら左右見比べ（既存の肺タップ）へ進む
- **E**: 既存の Before→After 画面を維持。撮り直し回数を添えて上達を可視化

## 廃止する anti-pattern

| 現状 | 改修後 |
| --- | --- |
| 部位の正解をノートが明言（誘導） | 依頼票（C）を読んで自分で選ぶ。誤選択は「依頼票をもう一度見る」導線のみ |
| 固定進行（ボタン送り） | 撮影タイミングという操作が画像品質を分岐させる |
| 失敗なし | ブレ→差し戻し→再撮影のループ |
| 全部タップで成功 | 見比べは維持しつつ、その前段に品質判定ゲートが入る |

## C_required / action_changes_result の担保

- C_required: 依頼票を開かないと撮影ボタンが出ない（開くこと自体を必須動線に）
  かつ部位誤選択の誘導ノートを削除
- action_changes_result: シャッターの押下タイミング → sharp / blurred の分岐、
  blurred のまま届ける選択 → 差し戻し分岐、撮り直し回数 → E 画面の文言変化

## MASTERY / REPLAY / CORE LOOP（改修後の想定）

- CORE LOOP: 呼吸サイクルを読んでシャッターを切り、写りを自分で良否判定して
  届けるか撮り直すか決める。考えどころは「いつ押すか」と「この写りで足りるか」
- MASTERY: 上手いプレイヤーは呼吸表示を先読みして1回でくっきり撮り、
  撮り直し回数が少ない（E 画面に回数が出る）
- REPLAY: 2回目は1発成功や、わざとブレさせて「なぜ息を止めるのか」を確かめられる

## 実装範囲

- `src/q1/XrayGame.tsx` の書き換えのみ（BodyInsideView は props 追加なしで流用、
  ブレ表現は CSS filter / SVG 属性で表現）
- 依頼票は既存 InfoCards パターンがあれば流用、なければ軽量実装
- `factory/taxonomy/component-reviews.json` の xray_shoot エントリを更新（reviewedHash 再計算）
