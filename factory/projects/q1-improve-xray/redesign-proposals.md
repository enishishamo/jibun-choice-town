# XrayGame 再設計 — 提案書（Stage 4, step 1-4）

## 1. Job reality 再確認（診療放射線技師）

医師の依頼に基づき撮影を計画・実行し、**診断に使える画像**を届ける仕事。

- 依頼票には症状・目的が書かれ、そこから撮影部位・範囲を技師が判断する
- **条件設定**: 体格・部位に応じて線量・管電圧を決める（強すぎ=真っ黒・被ばく増、弱すぎ=白くて読めない）
- **ポジショニング/範囲**: 必要な範囲が全部写るよう位置決めする。切れていたら撮り直し
- **息止め・タイミング**: 胸部は呼吸で動く。静止の瞬間に撮らないとブレる
- **被ばく最小化（ALARA原則）**: 無駄な撮影をしない。撮り直しは患者負担
- **画像の自己判定**: 診断可能な写りかを自分で見て、届けるか撮り直すか決める

## 2. Job-specific difficulties（taxonomy より）

1. `quality_judgment` — 写りの良否を自分で判定して届ける（中核）
2. `irreversibility` — X線は撃ったら取り消せない。被ばく予算
3. `counterpart_variability` — 患者ごとに体格・症例・指示が違う
4. `oversight_risk` — 見落とし（範囲切れ・左右差）
5. （time_pressure は本質でないため不採用）

## 3. Mechanic 候補（job-mechanics-map より）

self_quality_gate / limited_attempts / execution_precision / rule_matching_verification /
variable_conditions(modifier) / score_optimization(motivation)

## 4. 設計案（4案）

現行実装（58点）は limited_attempts + execution_precision + self_quality_gate +
variable_conditions を持つが、「部位選択が3ボタン・依頼票が答えを直接明示・
読影が左右タップのみ」の浅さが残る。以下は D（判断）を深くする案。

### 案A: 撮影範囲フレーミング（spatial judgment）

部位3ボタンを廃止し、**撮影フレームを患者の上でドラッグして範囲を決める**。
依頼票は「せきが続く。肺の中を見たい」等の症状ベース（=答えのボタン名は書いていない）。
肺が片方切れたフレーミングは「範囲切れ」で撮り直し。広すぎる範囲は被ばく増（予算-2）。

- 深まる判断: 症状→解剖の対応 + 範囲と被ばくのトレードオフ
- 懸念: ドラッグ精度がモバイルでシビアになりすぎないか（グリッドスナップで緩和）

### 案B: 患者適応の条件設定（rule application with judgment）

撮影前に**光の強さ（よわい/ふつう/つよい）を患者の体格を見て決める**。
C は原理だけ教える（「大きなからだは光が届きにくい→強め。小さなからだに強い光は
負担→よわめ」）。患者は毎回体格が変わる（3段階×症例）。誤条件は白すぎ/黒すぎ画像
→読めない→撮り直し（予算消費）。

- 深まる判断: C の原理を目の前の患者へ適用する（C_alone_determines_answer=false の教科書形）
- 懸念: 3×3の組み合わせ暗記に落ちないか（→体格表示を毎回ランダム・見た目で判断させる）

### 案C: A+B 統合ミニ（本命）

案Bの条件設定を主役に、読影も強化: 左右タップを廃止し、**虫めがねドラッグで画像を
自分で走査**して異常箇所をタップ指摘（位置まで当てる。上/下/左右の6領域）。
症例は「右上にモヤ/左下にモヤ/きれい」等の位置バリエーションへ拡張。
呼吸タイミング・被ばく予算・自己品質判定は現行を維持。

- 撮影フェーズ: 患者体格を見て光の強さを決める（B）→ 呼吸を読んで撮る（現行）
- 判定フェーズ: 白すぎ/黒すぎ/ブレ/OK を自分で判定（現行強化）
- 読影フェーズ: 走査して異常領域を指摘（新設・oversight_risk の実装）
- 深まる判断: 原理適用 + 実行精度 + 走査観察 + 位置特定。replay は体格×症例×位置

### 案D: 3患者キュー（prioritization 追加）

3人の患者（胸/腕/腹）を待たせ、順番と各撮影をさばく。
- 懸念: Q1の尺・実装規模を超える。医療編は1患者の物語構造（9章で1人を追う）と不整合

## 6. 最終決定（Claude synthesis × Codex 独立審査）

- Codex 審査: A(82) > C(76) > B(68) > D(40)。C は「5機構同時で小学生に過積載」、
  A は「positioning/collimation の職業判断の最良翻訳」（proposal-review.result.json）
- Claude 初期推奨は C だったが、過積載指摘を妥当と判断し **案A を採用**
- 統合仕様:
  - 部位3ボタン廃止 → 撮影フレームの位置（うえ/まんなか/した）×サイズ（小/中/大）を
    患者の見た目（体格・写り位置）から判断して決める。スナップ式でドラッグ精度を要求しない
  - 正解オーバーレイは出さない。C は原理のみ（肺の場所・大きいからだは大きく写る）
  - 範囲切れ=読めない/過大範囲=被ばく2消費（ALARA）。連続的なコスト設計
  - 呼吸タイミング・被ばく予算5・自己品質判定は維持
  - 「どちらの肺があやしいか」は合否ゲートから外し、気づきメモとして E 演出へ
    （読影診断は医師の本分 — Codex authenticity 指摘を採用）
  - 症例変動: 患者体格3 × 写り位置 × モヤ(右/左/なし)
- 実装方針: ロジックを src/q1/xrayLogic.ts へ分離し、
  factory/harness/gameplay-qa-xray.mjs で実挙動を自動検証（連打/C無視/全選択/最短/エッジ）
