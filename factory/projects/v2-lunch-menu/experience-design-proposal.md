## 3'''. 【2026-09-21 更新②】GPT Visual Review（給食担当経由）への対応 — PLAY UI 修正

Design Owner（GPT）の Visual Review（Human 経由、2026-09-21）。料理 asset の方向性（大きさ・統一感・
「押したくなる」見た目）は維持。PLAY 画面は未完成扱いで、次の機能へ進まず以下を修正した。
WORLD MAP / JOB REVEAL / 好きの種には進まない。守るもの: 説明文を増やさない・知らないキャラを足さない・
余白埋めの装飾を足さない・総合 score を復活させない・正解／不正解表示に戻さない・「触る→反応→意味が分かる」。

| 指摘 | 対応（実装、TEMP_IMPLEMENTATION_ONLY・GPT 上書き可） |
|---|---|
| **状態 cue**: トレー下の丸 ring 群＋四角 mark 群は静止画で意味が分からない。説明文で解決しない。「料理を置く→料理から何かが飛ぶ→献立の何かが変わった」が視覚で分かること。三色食品群の知識を前提にしない。抽象記号の横一列（status dashboard）感を弱め「献立ができていく」感覚へ | 抽象記号を撤去。**トレーの手前に置かれた 3 つのかご**（生成 asset、前面の小さな絵タグ＝さかな／ごはん／はっぱ。言葉なし）に、置いた料理から**粒が飛んで中にたまる**（初回完成時は全皿から、以後は置いた皿から即時）。たりない＝かごがスカスカ（空の点線の輪が脈打つ）、おおすぎ＝粒が縁からこぼれて揺れる。ルール cue は**トレー上の料理の場所で起きる**: しお＝白い粒が皿に降る、あぶら＝皿の下から油が垂れて水たまり、かぶり（材料／作り方／種類）＝同じ 2 皿の間を粒が跳ねて往復、たりない種類＝トレーの空き面に点線の輪＋配膳台のその段が浮く |
| **料理カード**: 選択済みをカードごと薄くすると「選んだ／選べない／届かない／disabled」が競合。届かない状態を明確に残す | 選択済み＝料理がカードから**いなくなり**、置き場所に薄い輪＋小さなチェック（fade なし）。届かない＝料理はそこにあるが灰色＋コーラルのバッジ＋タップで揺れる。別の visual language に分離 |
| **開始画面**: 「トレー＋料理カード一覧」は選択フォーム感。MICRO LOOP（触りたくなる→置いた瞬間が気持ちいい→次も置きたくなる）を強く。pick-up→トレーへ移動→pop/bounce→小さな particle | タップで料理が**カードから浮き上がり、トレーの枠まで飛んで着地**（380ms、影が縮む）→ pop → 7 粒の小さな burst。着地までスロット側の料理は非表示（二重に見えない） |
| **画面密度**: 375×812 で候補を見るために長くスクロールする構造を再検討。巨大 3 列カードを縦に並べる必要はない。トレー主役・選びやすく・次の候補も見たくなる。料理 asset を小さくしすぎない | カード面を廃止し、**1 枚の配膳台**（画面下部を埋める面）に料理を **種類ごとに 4 段（主食 2／主菜 3／副菜 2／汁物 2）**で並べる（配膳順 V-A1）。9 品すべてがスクロールなしで見える。料理は 98px（従来と同等以上）。上部に帯（トラックが来る／学校が現れる場所）を常設し、トレーと重ならない |

再提出する 5 状態（`factory/harness/v2-lunch-shots.mjs`）: 02 開始直後 / 02b・02c 1 品置いた瞬間 /
03・04 4 品完成して状態 cue が出た直後 / 05 1 品交換して状態が変わった直後 / 06 EVENT 発生直後。
04 については「初見の小学生が何が起きたか視覚だけで推測できるか」を独立 Art QA で評価する。

## 3. ゲームロジック案（STEP 4、初版・記録）— 「87 → 94 → 96 は何で生まれるか」

共通前提（LOCKED からの制約）:
- 唯一の正解なし・複数解あり・0/1 判定なし・「隠れ正解当て」なし・失敗を文章で説明しない
- 料理の属性は**隠さない**（盤面に見える。見せ方は GPT）— 「Cを見ないと解けない」を、読む資料ではなく**料理そのものの見た目**で満たす
- スコアは 60〜100 帯の改善型

### 案A（推奨）「そろえる × なじむ × とどく」— 献立作成の 3 つの判断を 1 つの数字に畳む

**ゲーム化している実際の判断（NEEDS_VALIDATION 付き）**
1. **そろえる**: 主食・主菜・副菜・汁物（＋果物/デザート）の基本形をそろえ、三色食品群
   （赤=からだをつくる／黄=エネルギー／緑=ちょうしをととのえる）を偏りなく満たす
   ＝ 学校給食摂取基準に基づく栄養バランス判断の**翻訳**（V-A1, V-A2）
2. **なじむ**: 組み合わせの相性（主食と汁の和洋、揚げ物の重なり、味の重複）＝ 献立の一貫性・脂質過多回避（V-A3）
3. **とどく**: 食べてもらえるか（嗜好・残食）＝ 「栄養満点でも残されたら届かない」判断（V-A4）

**子どもが操作するもの**: 料理をタップ→トレーに入る／トレー上の料理をタップ→戻る（入れ替え）。それだけ。

**スコアの骨格（仮値）**: `score = 100 − Σペナルティ`
| 要素 | 見え方（絵で） | 仮ペナルティ |
|---|---|---|
| 役割が欠ける（主食なし等） | トレーの枠が「空いてる感」 | −8 / 役割 |
| 役割が重なる（ごはん＋パン） | 2 つが同じ形 | −6 |
| 三色のどれかが薄い | 料理の三色マーク合計が少ない | −5 / 不足 1 |
| 三色のどれかが多すぎる（黄ばかり） | 同色ばかり | −2 / 超過 1 |
| 重い料理の重なり（揚げ物×2） | 油っぽい見た目が 2 つ | −4 |
| 和洋の不一致（パン＋みそ汁） | — | −3 |
| 食べにくい／残されやすい料理の重なり | 人気の低い見た目（GPT 判断） | −2 / 個 |

**87 → 94 → 96 の例（仮値）**
- 初期: ごはん・からあげ・ポテトサラダ・コーンスープ・プリン
  → 緑 不足 −5、黄 超過 −2、重い重なり（からあげ＋ポテト）−4、和洋不一致 −2 ＝ **87**
- ポテトサラダ → 野菜のごまあえ: 緑 解消 +5、黄 超過 解消 +2 ＝ **94**
- コーンスープ → とうふのみそ汁: 和洋不一致 解消 +2 ＝ **96**
- ここで からあげ → さけの塩焼き にすると: 重い重なり 解消 +4、ただし「とどく」−2 ＝ **98**
  ／ 逆に さけ → からあげ に戻すと 96 に下がる — **上がる方向が一つではない**（トレードオフ）

**複数解**: 96〜100 に到達する組み合わせは 6〜8 料理で十数通り（実装時に `lunchMenuLogic.ts` の
総当たりで検証し、`factory/harness/gameplay-qa-v2-lunch-menu.mjs` で「唯一解でない」「初期状態から
3 手以内で +7 以上改善できる」「隠し属性なし」を機械検証）。

**EVENT（§8）との整合**: 配送トラブルで**食材が使用不可**になる（例: 魚が届かない）。使用不可の料理は
トレーに入らず、既にトレーにあれば外れる → スコアが下がる → 再構成。ペナルティではなく**制約**なので
「答えを教える文章」が不要。トラブルの内容（何が届かないか）を将来ランダム化すれば AGAIN の土台になる。

**「もう少し良くしたい」が起きる理由**: 数字が 100 に届かない・上下する（単調増加でない）・入れ替えが
1 タップで即反応・トレー上でそのまま試せる（画面遷移なし）。

### 案B「食べてもらえた栄養」— 1 本のメーター
`score = Σ(料理の栄養点 × 食べられる割合)`。人気だが栄養の薄い料理と、栄養は高いが残されやすい料理の
トレードオフに集中。長所: 数字の意味が 1 つで強い、仕事の核心（届いてこそ栄養）に直結。
短所: 「そろえる」判断が消える、残食率の仮値が多くなる（V-A4 の比重大）、組み合わせパズル感が弱い。

### 案C「三色ぬりつぶし」— 純パズル
トレー脇に赤黄緑の 3 ゲージ。料理を置くと塗られ、過不足で減点。長所: 最も視覚的、文字ゼロで成立。
短所: 「ゲージを満たす」作業になり、役割・相性・嗜好という**仕事の判断が残らない**。隠れ正解当てに
近づく。単独採用は非推奨（案A の一要素として吸収済み）。

**推奨: 案A**（案B の「とどく」を内包）。理由: 献立作成の判断が 3 種類残り、トレードオフと複数解が
構造的に生まれ、EVENT が制約として自然に接続する。

### STEP 5 自己レビュー
| 観点 | 案A | 案B | 案C |
|---|---|---|---|
| 隠れ正解クイズになっていないか | ◯ 属性は盤面に見える・複数解 | ◯ | △ ゲージ充足作業 |

## 8. 4 つの LOOP に対する見立て（設計段階）

- MICRO: 1 タップ＝即座にトレーへ入る／結果が動く。reaction の見た目は GPT（DN-05）。技術的には 100ms 以内の状態反映・CSS transform ベースの animation で担保。
- GAME: 数字が上下する・EVENT で崩れる・複数解がある → 「もう 1 回」の材料はある。ただし初回プロトタイプは EVENT 1 種・料理 6〜8 種固定。AGAIN が本当に起きるかは子どもテストで判定。
- SESSION: MAP RETURN で「こんだて」解決＋「はこぶ」異変。ここが未実装だと SESSION LOOP は成立しない → 最小 MAP を同スコープに（§1）。
- META: 好きの種 1 つを Ver.2 の進捗キーに保存するところまで。ノート・アイテムは接続点だけ用意（実装しない）。
