# 「動物園に赤ちゃんが生まれた」— Game Design（Stage 8・再現性テスト）

research: research.result.json（Codex委譲）/ 選定: selection.md / 規約: game-critic-v2.md
安全配慮（research準拠・全ゲーム共通）: 病気・育児放棄・人工哺育を「失敗の罰」にしない。
動物の死を扱わない。失敗は「先輩・獣医チームが引き継いで教わる」形。野生動物をペットの
ように描かない。「触る・抱く」を報酬にしない。体重増=必ず健康、とは表現しない。

## World 構造

- **A**: 動物園のバックヤード（保育室・診察室・調理場）→ 展示場
- **B**: 生まれたレッサーパンダの赤ちゃんが、健やかに育ち、無理なくデビューできるようにする
- **E**: 「見せる」より「動物が選べる」展示へ。来園者のマナーが動物福祉を支える
- 物語: 誕生→毎日のケア→健康チェック→餌づくり→デビュー判断（requires 連鎖）

## Job-specific difficulties → mechanics（先に難しさ）

| job | difficulties | matched mechanics | Stage 7 との重複 |
| --- | --- | --- | --- |
| 飼育員 | dynamic_state, oversight_risk, prediction | **傾向読みトリアージ**（delayed_feedback系） | なし |
| 獣医師 | incomplete_information, safety_tradeoff, irreversibility | **risk_reward**（負担予算×検査選択） | gas=部分情報だが、負担コスト×蓄積型で構造が異なる |
| 栄養担当 | counterpart_variability, limited_resources, oversight_risk | **combination/配分 + 禁忌rule** | curb=単流の受入判定、こちらは相手別の組立 |
| 展示企画 | safety_tradeoff, counterpart_variability, quality_judgment | **resource_tradeoff + self_quality_gate（延期判断）** | なし |

world 内 primary 重複 0。UIオラクル禁止・単独点検で確定しない証拠設計・義務ルールの
機械強制（Stage 7 の実装レビュー教訓）を初版から適用する。

## Q1-1: baby_care（飼育員）experienceId: zoo-care

- **Goal**: 5日間、赤ちゃんの毎朝の見立て（順調/授乳を調整/獣医に相談）を正しく続ける
- **Core Action**: 体重を量って成長曲線に点を打つ → 日誌（授乳・便・活動）と合わせて3値判定
- **C**: 成長曲線の読み方（**単発の数値より傾向**=research）/ 判定のめやす表
  （2日連続の停滞+飲み残し→調整、体重減+便異常/ぐったり→相談、1日だけの小さな凹み→様子見）/
  飼育日誌
- **D**: 日ごとにランダムな系列（順調・一時的な凹み・調整で直る停滞・要相談サイン）。
  過剰反応（順調なのに相談）も過小反応（サイン見逃し）もミス。**単日データでは判定不能**
- **Constraint**: ミス予算1（2回目で先輩が交代=罰は学びの形）。5日目まで
- **Mastery/Replay**: 系列と日誌がランダム。傾向を読める子は凹み1日で騒がない
- CORE LOOP: 量る→曲線に足す→日誌と重ねて3値判定。考えどころは「これは傾向か、単発か」
- MASTERY: 初心者は毎日の数字に一喜一憂。上級者は曲線の形と日誌の複数サインで判断
- REPLAY: 系列が毎回違う。「様子見が正解の日」があるので相談連打は通らない
- NOVICE VS EXPERT: 上級者は「体重減+便異常」の複合サインだけを相談に上げる

## Q1-2: zoo_checkup（獣医師）experienceId: zoo-checkup

- **Goal**: 触れない患者の不調の原因を、動物への負担をおさえて特定し、方針を決める
- **Core Action**: 検査メニューから選ぶ（負担コスト付き）→ 所見を集める → 診断+方針
- **C**: 検査メニューと負担コスト（日誌/カメラ観察=0・視診=1・糞便検査=1・保定して血液=3）/
  「負担の小さい方法から」「結果が方針を変えるか」の原則（=research D）/ 所見の意味
- **D**: 症例3種ランダム（おなかの虫・食べ過ぎによる軟便・けがによる痛み）。負担予算4。
  **証拠設計**: 0負担の観察だけでは2候補までしか絞れない（単独チェック確定なし）。
  糞便検査が虫を確定/否定、視診がけがを確定/否定。血液(3)は「全部わかるが予算をほぼ使う」
  リスク選択として存在（使っても勝てるが負担グレードが下がる）
- **Constraint**: 予算4を超える検査は選べない。診断は1回勝負（誤診→治療が空振りして
  獣医チーム会議で学び直し=失敗）
- **Mastery/Replay**: 低負担ルートで確定できる順を組めるか。症例ランダム
- CORE LOOP: 「次のひと調べで、どれだけ絞れて、どれだけ負担か」を毎手判断
- MASTERY: 初心者は血液に飛びつき負担大。上級者は観察→的を絞った1検査で確定
- REPLAY: 症例で最短ルートが変わる
- NOVICE VS EXPERT: 上級者は「結果が方針を変えない検査はしない」原則で動く

## Q1-3: feed_prep（栄養担当）experienceId: zoo-feed

- **Goal**: 飼料日量表どおりに、3にんぶんの朝の餌を組み立てる（母・赤ちゃん・となりのヤギ）
- **Core Action**: 各動物のトレイへ食材カードを配分（量はS/M）→ 日量表と照合して提供
- **C**: 飼料日量表（動物×食材×量。授乳中の母は増量=research）/ 禁忌メモ
  （ヤギにキャベツ類の与えすぎ注意・冷凍魚は解凍済みのみ 等、施設のきまりとして明示）/
  在庫ボード（竹は2つしかない→取り合いの優先判断）
- **D**: 動物ごとに正解が違い（counterpart）、在庫が足りない食材は優先順位（授乳中の母を
  優先）を判断。禁忌・量違いは提供前チェックで自分の目で見直す（提供は1回勝負）
- **Constraint**: 在庫制約・提供後の差し戻し1回で先輩と作り直し（2回で交代）
- **Mastery/Replay**: 日量表と在庫がランダム（母の要求量・在庫数・禁忌対象が変わる）
- CORE LOOP: 表を引く→配る→足りない分の優先を決める→提供前に自分で照合
- MASTERY: 上級者は配る前に在庫の競合を見抜き、優先順位から逆算して組む
- REPLAY: 在庫と要求が毎回変わり、同じ配分の暗記は通らない
- NOVICE VS EXPERT: 上級者は「誰を優先すべきか」を理由（授乳・成長段階）で説明できる

## Q1-4: debut_plan（展示企画）experienceId: zoo-debut

- **Goal**: 練習記録を読んでデビュー初日のプランを組み、当日のサインを見て続行/縮小/中止を判断
- **Core Action**: 公開プラン（時間の長さ×観覧距離×人数制限）を組む → 初日シミュレーション
  → ストレスサインに応じて運営判断
- **C**: 展示練習記録（自分から出たか・隠れ時間・驚き反応=research の実項目。**敏感さが
  ランダム**）/ ストレスサインの読み方（往復行動・隠れたまま・採食中断）/
  「必ず見せるより、隠れる選択を優先」の原則
- **D**: プランの各要素がストレス予測と来園者満足に効く（トレードオフ）。練習記録が
  敏感寄りなら短時間・遠距離・制限ありから。当日サインが出たら**縮小・中止する勇気**
  （self_quality_gate。中止は失敗ではなく正しい判断として加点）
- **Constraint**: ストレスサイン3つ目で動物が隠れて出てこなくなり「初日は中止」=失敗では
  なく再挑戦（ただし判断が遅れた記録は残る）。**攻めプランで押し切る戦略は成立しない**
- **Mastery/Replay**: 敏感度と当日イベント（団体客到着・大きな音）がランダム
- CORE LOOP: 記録を読む→プランを組む→当日のサインを見て運営を調整する
- MASTERY: 初心者は満足度を狙って攻めて中断続き。上級者は記録から初期プランを当て、
  サイン1つで先回りに縮小する
- REPLAY: 敏感度・イベントが毎回違う。「中止が最良判断の日」も生成される
- NOVICE VS EXPERT: 上級者は「今日は見られないことがあります」と言える（=研究の実は！）

## 数値仕様（正本は src/q1/zooLogic.ts・検証は factory/harness/gameplay-qa-zoo.mjs）

確定値（QA実測は factory/harness/gameplay-qa-zoo.mjs、48/48 PASS。全制約は zooLogic.ts の
状態機械が強制 — BabyState/ZooState/FeedState/DebutState。UIは規則を写すだけでゲートしない）:
- baby_care: 5日・ミス予算1（2回目で先輩交代）。**毎週かならず「調整の日」1つと「相談の日」
  1つを含む生成**（+40%で良性の凹み）→ ok連打/相談連打/調整連打は全て完走不能（0/500）、
  ルール準拠プレイ100%。良性の凹み出現42%（過剰反応が罰される）
- zoo_checkup: 負担予算4・コスト{日誌0,カメラ0,視診1,糞便1,血液3}・症例3種。
  **血液以外のどの単独検査でも3原因は割れない**（機械検証）。0負担観察→的を絞った1負担検査で
  全症例確定（平均負担1.0）。**血液=保定は12%で動物の強い抵抗により当日中止**
  （research「追跡・保定・麻酔の危険と比較」の機械化 — 高負担直行には実リスク、
  低負担ルートにはリスクなし。機械検証済み）。盲目診断は32%どまり
- feed_prep（**BLOCKER修理で導出型へ再設計**）: 表は「規則」だけを与え、正解は今朝の
  日誌データから導く — 赤ちゃんのミルク量=今朝の体重×500g線（440〜584gで毎回変動）、
  母の野菜=授乳メモ（多め→M(2)/ふつう→S(1)）。**野菜が足りるかはフラグでなく算数**:
  在庫は母の必要量+0〜2で生成され、「母の必要量を計算→ヤギのSが残るか」を自分で数える
  （同じ在庫2でも母が多め日なら不足・ふつう日なら充足）。トレイ照合は順序非依存。
  静的暗記トレイは84%の朝で差し戻し・パン=デコイ・導出プレイ100%・差し戻し2回で先輩交代
- debut_plan（**BLOCKER修理×2**）: 研究の運用階段を規則化 — サイン0の中止は拒否・
  **サイン1でも中止は拒否（単一行動で決めない: まず縮小）**・中止が認められるのは
  「サイン2つ=パターン」かつ**縮小を試した後**のみ。序盤（2時間帯未満）での中止は
  「仕切り直し（postponed）」= プラン不適合の帰結。縮小はレバー選択（各1回・各-2）、
  人数制限は積極的に鎮静（-1）。perfect = サイン0×縮小≤1のフル実施 or パターン対応の中止。
  **C（練習記録）の価値は品質に機械的に現れる**: 記録無視の固定プランは成功はできても
  perfect率が明確に劣る（0.32 vs 0.43、QA比較検証）。攻め押し切りは96%失敗

## 既存ゲームとの非重複（明示比較）

- baby_care（傾向トリアージ）: clue_board/observe_care は「見る対象を選ぶ」、本作は
  「時系列の形を読み単発と傾向を区別する」— 判定対象がデータの形そのもの。既存に無し
- zoo_checkup（負担予算×検査蓄積）: gas_watch は時間予算×1回依頼、lab_check は全件必須。
  本作は各検査に福祉コストが付き「結果が方針を変えるか」で取捨する蓄積型。既存に無し
- feed_prep（規則×当日データ導出＋在庫優先）: recipe_balance は連続配合の探索、
  curb_check は単流の受入判定。本作は相手別トレイを規則適用で導出し、競合資源の優先を
  理由で決める。既存に無し
- debut_plan（トレードオフ計画×福祉ゲート運営）: plan_mix 系は静的組合せで終わる。
  本作は計画のあとに「当日運営のリアルタイム判断」（縮小レバー・honorable stop）が続く。
  既存に無し

## 設計レビュー第3回（FAIL 48）への対応記録
機械修理（zooLogic.ts に実装、QA 48/48で検証）:
- feed_prep: feedValidate がトレイ全数を検査（余剰スロット/全のせ exploit を拒否）
- zoo_checkup: 所見ゼロの診断を拒否（勘での1/3勝ちを封鎖）／blood は低負担2手の後のみ（保定=最後の手段を機械強制）
- baby_care: 週レイアウトを12基本配置に一般化（位置の暗記無効化）
- debut_plan: 縮小レバー3種に異なる因果（cap↔混雑/widen↔近接/shorten↔長時間）、園の期待値を練習記録に連動（expectMin: calm=5）、done_early の perfect はプラン適合時のみ。記録無視プランとの品質差 0.39 vs 0.19、calmの日は記録を読まないと期待ゲート自体を通過不能。

採用しない指摘（較正裁定に基づく設計判断）:
- 「baby_care は C カードで正解が決まる」— ユーザー較正裁定は「C単独で答えが確定する場合のみ問題」。baby_care の C は規則であり、正解は毎朝の曲線の形・日誌サイン・前日履歴（今日のデータ）との照合で決まる。C だけでは答えは出ない（waste世界 curb_check と同じ構造で、実装レビューPASS済みの較正）。
- 「feed_prep が唯一解の再現」— 飼料日量表は現実に決定的な規則であり、判断は在庫の算術と授乳優先の適用に宿る（研究準拠）。
