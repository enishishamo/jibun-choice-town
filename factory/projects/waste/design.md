# 「ごみのゆくえ」清掃工場編 — Game Design（Stage 7）

research: research.result.json（Codex委譲・出典ヒント付き）/ 選定: selection.md
較正規約: factory/rules/game-critic-v2.md / 原則: A→B→C⇄D→E

## World 構造

- **A**: 朝のごみ集積所 → 清掃工場（ピット・炉・中央制御室）→ 最終処分場
- **B**: 「けさ、きみの家から出た1袋のごみ」が安全に処理・管理されるまでを成立させる（埋立後も長期管理される — 「土へ還る」ではない）
- **E**: 発電・灰の資源化・処分場の余命（全国平均24.8年/2023年度・環境省）→ 3Rへの接続
- 物語: 1袋のごみを4つの仕事がリレーする（章は時間の流れで requires 連鎖）
- 安全配慮（research の safety_sensitivities 準拠）: 巻き込まれ/火災を刺激的に描かない・
  スプレー缶穴あけを全国共通正解にしない・リチウム電池は「大人へ知らせる」導線

## Job-specific difficulties → mechanics（先に難しさ、後から機構）

| job | difficulties (taxonomy id) | matched mechanics (library) |
| --- | --- | --- |
| ごみ収集作業員 | oversight_risk, counterpart_variability, time_pressure(弱) | **rule_matching_verification** + variable_conditions |
| 焼却炉運転員 | dynamic_state, prediction, safety_tradeoff | **dynamic_state** + resource_tradeoff(ピット資源) |
| 環境計測担当 | incomplete_information, oversight_risk, quality_judgment | **partial_information** + rule_matching(基準照合) |
| 処分場管理者 | limited_resources, prediction, safety_tradeoff | **resource_tradeoff** + spatial集約 + prediction（天気） |

primary mechanic の world 内重複: 0（多様性ゲート PASS）。
既存39ゲームとの重複回避: 分別仕分け（sort_out）は作らない。収集は「仕分け」でなく
「回収可否の現場判定＋対応選択」。原因切り分け（line_debug の弱点だった
固定正解・無コスト総当たり）は症例ランダム化＋調査コスト＋誤対応即時実害で回避。
landfill_ops は日次オペレーション（配置×覆土×天気）で、スライダー配分の
allocate_and_forecast とは操作も失敗因果も異なる。
Q1-1（多数の即時照合）と Q1-3（単一症例の逐次調査）は「照合」の粒度と時間構造が
異なる別系統として設計（前者=件数×視覚手がかり、後者=調査コスト×消去法）。

## Q1-1: curb_check（ごみ収集作業員）experienceId: waste-collect

- **Goal**: 集積所の袋を全て正しく処理して収集を完了する（積む/残す＋理由）
- **Core Action**: 袋を観察 → ルール表と照らす → 「積む」or「理由シールを貼って残す」
- **C**: 今日の収集区分（燃やすごみ・指定袋の色）/ 違反シールの理由3種 / 危険物の見分け
  （スプレー缶・電池は収集車で発火の恐れ = research C）。**袋の中身は見た目でしか分からない**
- **D**: 半透明袋の中身（ランダム生成）を見て判定。危険物入りを積む→収集車から煙→即失敗。
  分別違いを積む→工場から連絡→ミス加算。正しい袋を残す→住民が困る→ミス加算。
  残す時は対応を選ぶ: 分別違いシール / 指定袋シール / **危険物は「はなれて営業所へ連絡」**
  （シールでなく隔離・連絡 = research の作業停止・事業所連絡手順。E画面で
  「リチウム電池は大人・自治体窓口へ」の安全導線を子ども向けに明示）
- **Constraint**: ミス予算1（2回目のミスで「今日の収集が止まった」）・危険物積載は即失敗
- **Feedback**: 判定ごとに即時（積載/シール演出）※正解は事前に教えない
- **Failure/Retry**: 症例セット再抽選で最初から（暗記持ち越し不可）
- **Mastery**: 全袋一発正解＋正しい理由（E画面で「プロの目」演出）
- **Replay/Variation**: 袋6件を毎回ランダム（違反2〜3保証・危険0〜2・収集区分も毎回変わる）。
  違反≥2＋ミス予算1により「全積み」はどの症例でも完走不能（QA実測 0/500）
- **Result(E)**: 収集車が工場へ。「残す判定も仕事」（研究の実は！）
- CORE LOOP: 袋を1つずつ観察し、ルールと突き合わせて積む/残す/理由を決める。考えどころは
  「見た目のどこが手がかりか」と「どの理由が正しいか」
- MASTERY: 上級者は危険物の視覚サイン（缶の形・電池マーク）を素早く見抜きミスゼロで完了
- REPLAY: 袋構成が毎回変わる。危険物ゼロ回もあり「全部積めば良い」が常に正解ではない
- NOVICE VS EXPERT: 初心者は「汚れて見える=残す」等の見た目バイアスで誤る。上級者は
  区分・袋・中身の3点照合を機械的に回せる

## Q1-2: pit_crane（焼却炉運転員）experienceId: waste-incinerate

- **Goal**: 8ターン、炉温を850℃以上・1000℃未満に保つ（ねらい帯は850〜950。951〜999は「注意帯」で、失敗ではないが安定度評価が下がる=pitStability）
- **Core Action**: ピット3×3のごみ（乾/湿/混合）をクレーンで「つかんで投入」or「まぜる」
- **C**: 炉温計と「**この工場の運転マニュアル**」（850℃未満はダイオキシン類の生成抑制に
  反する=research の一般則。950℃/1000℃の上限帯は**架空施設の施設固有値**と明示）/
  ごみ質の見た目（色: 乾=茶・湿=青緑・混合=緑）/ 「混ぜると質が均一になる」原理 /
  毎ターンの搬入予告
- **D**: 投入するごみ質で炉温が変化（乾+80/混+30/湿-60、無投入-70）。まぜる（隣接2マス）で
  湿+乾→混合2つ。搬入が湿ゾーンを増やす回もある（dynamic）。**どこを掴むか・いつ混ぜるか**
- **Constraint**: 850℃未満を2ターン連続→炉停止（失敗）。1000℃超→炉を傷め失敗。
  ピットの同じ列ばかり掘ると枯れて選択肢が減る
- **Failure/Retry**: 初期配置・搬入パターン再抽選で再挑戦
- **Mastery**: 「まぜるターン」を先読みで確保し温度振れ幅最小でクリア（E画面に安定度）
- **Replay/Variation**: 初期3×3配置と搬入スケジュールがランダム
- **Result(E)**: 蒸気タービンで発電・灰は1/20の体積に（research fact）
- CORE LOOP: 温度と手持ちのごみ質を見て「今投入すべき質」か「先に混ぜて仕込むか」を毎ターン判断
- MASTERY: 初心者は乾いたごみを使い切って温度墜落。上級者は湿ごみを早めに混ぜて
  「混合の在庫」を作り、搬入の乱れを吸収する
- REPLAY: 配置と搬入が毎回違うため、同じ手順の暗記では安定しない
- NOVICE VS EXPERT: 上級者は2ターン先の温度を暗算し、無駄な高温（炉傷み）も避ける

## Q1-3: gas_watch（環境計測担当）experienceId: waste-measure

- **Goal**: 計器アラートの本当の原因を、煙突から基準超過が出る前に特定して正しく対応する
- **Core Action**: 調べる対象を選ぶ（コスト1/回）→ 証拠を読む → 原因を特定 → 対応を選ぶ
- **C**: 連続計器の時系列（CO/HCl/炉温のミニグラフ）/ 管理値ライン / 点検先4つ
  （薬剤タンク残量・バグフィルタ差圧・計器の校正記録・炉の燃焼状態）/
  「本当の上昇か計器異常かを切り分ける」手順（research D そのもの）
- **D**: 原因は3種からランダム（薬剤切れ / 計器ドリフト / 不完全燃焼）。点検は時間コスト
  （**4コマ・点検は最大3回**。全点検の総当たりは構造的に不可能）。**症例生成の整合規則**: アラート計器は原因に従属
  （薬剤切れ→HCl・不完全燃焼→CO・ドリフトのみ両計器あり得る）。証拠マトリクスは
  wasteLogic.ts の inspect() に固定実装（校正切れはドリフト時のみ陽性等・矛盾症例は
  生成されない）。**対応は計測担当の職掌内の「依頼・連絡」**: 保全へ薬剤補給を依頼 /
  計器の校正を手配 / 運転員へ燃焼調整を連絡 /（過剰反応）炉停止を要請。
  誤った依頼→まちへの説明がつかず失敗
- **Constraint**: 時間4コマ・対応は1回勝負（4対応×3原因）。差圧点検は全原因で「参考情報」の
  デコイ（情報価値の低い点検を見抜くのも習熟）。**段階開示UI**:
  最初はアラート計器のみ表示。点検するたび証拠カードが1枚ずつ開き、容疑リストが
  視覚的に消し込まれる（小4の認知負荷対策）
- **Failure/Retry**: 原因・波形を再抽選
- **Mastery**: 最少点検（2手）で確定させ、余裕を残して対応
- **Replay/Variation**: 原因×アラート計器×波形の組合せがランダム
- **Result(E)**: 測定結果は公開される制度（research fact）—「まちに説明できる」ことが仕事
- CORE LOOP: 「どれを点検すれば原因候補が一番絞れるか」を考えて調べ、証拠がそろったら踏み切る
- MASTERY: 情報価値の高い点検順（例: まず校正記録で計器説を消す）を組める
- REPLAY: 同じアラートでも原因が違う。前回の答えを貼ると失敗する
- NOVICE VS EXPERT: 初心者は目についた対応へ飛びつく。上級者は「切り分けてから動く」

## Q1-4: landfill_ops（最終処分場管理者）experienceId: waste-landfill

【design critic 指摘による再設計】旧 landfill_plan（市全体の予算配分）は
(1) 管理者の職務（提案・調整）を越える (2) 失敗因果が研究と不一致
(3) 既存 allocate_and_forecast と実質同一 のため廃棄。研究が挙げる処分場固有の職務
（受入・埋立区画・**即日覆土**・**浸出水管理**）をそのままゲーム化する。

- **Goal**: 5日間、搬入を断らず・浸出水をあふれさせずに埋立地を回しきる
- **Core Action**: 毎日届く搬入（焼却灰・不燃残さ）を3つの区画へ配置 → 夜、その日さわった
  区画（作業面）に覆いをかける（**日課**。覆いは次にさわるまで持続）→ 夜が明けて結果
- **C**: 覆土の意味（飛散・におい・雨水の侵入を防ぐ = research）/ 浸出水の仕組み
  （雨がごみに触れると汚れた水になり、処理タンクで浄化してから流す）/ 天気予報 /
  区画容量と覆土材の残量 / タンクの1日あたり処理量
- **D**: **配置判断が覆いの需要を決める**: さわる区画が少ないほど毎晩の覆いが少なくて済む。
  型ルール（灰/不燃は別区画=この施設の受入区分。灰は資源化のため分けて管理）と容量が
  配置の自由を縛る。覆いは義務であり戦術ではない——ただし今週は納入遅れで材料が
  足りない日があり、**足りない夜だけ**どの作業面を覆うか（天気を読んだ優先順位）を決める
- **Constraint**: 区画3×容量5・覆土材7/週・タンク容量6（超過失敗）・苦情3で失敗・
  **受入基準: ⚱️焼却灰と🪨不燃残さは同じ区画に入れない**（置ける区画が無い搬入=受入不能で失敗）
- **Failure/Retry**: 搬入量・天気の再抽選で再挑戦
- **Mastery**: 埋立の集約と覆土のタイミングで、覆土材を余らせ水位も低く保つ（E画面で評価）
- **Replay/Variation**: 5日間の搬入スケジュール・雨の夜（1〜3回）がランダム
- **Result(E)**: 「埋め立てた分だけ処分場の残りは減る」— 残余年数=残余容量÷年間埋立量の式と
  全国平均24.8年（2023年度・環境省）を提示し、灰の資源化・3Rの「提案」も仕事だと結ぶ
  （提案=research の D。ゲーム外の語りで扱い、職務逸脱を避ける）
- CORE LOOP: 「どの区画に埋めるか」と「今夜どこへ覆土するか」を天気と残量で毎日決め直す。
  考えどころは集約（覆土節約）とあふれ（容量）のトレードオフ
- MASTERY: 初心者は毎晩全部に覆土して材切れ、または晴れ夜に無駄がけ。上級者は予報を読み、
  埋立を1〜2区画に集約して覆土回数そのものを減らす
- REPLAY: 雨の並びと搬入量で最適な集約度が変わる。タンク余裕を使う「攻めの節約」も選べる
- NOVICE VS EXPERT: 上級者は「明日の雨×むき出し区画数=増水」を暗算し、覆土材の使いどきを逆算する

## 数値仕様（正本は src/q1/wasteLogic.ts・検証は factory/harness/gameplay-qa-waste.mjs）

### curb_check
- 袋6・違反1〜3（危険40%/分別35%/袋25%重み）・ミス予算2（2回目で終了）・危険物積載は即失敗
- **収集区分が毎回変わる**（燃やすごみの日/プラの日）: OK品目と分別違いが入れ替わるため、
  ルールカードを毎回読む必要がある（C_required の構造保証）
- QA実測: 全積み10.4%勝/全残し0%/ランダム0.6%/正解プレイ100%

### pit_crane
- 初期温度900・帯850〜950（1000以上即失敗・850未満2ターン連続失敗）
- 効果: 乾+80/混+30/湿-60/無投入-70。まぜる=隣接の乾+湿→混合2（そのターン投入なし）
- 初期配置: 乾4/湿3/混2 をシャッフル（生成制約）。搬入: 3〜4T目と5〜7T目に湿優勢2個ずつ空きマスへ
- QA実測: 無操作0%/乾連打0%/ランダム6.6%/方針プレイ100%

### gas_watch 証拠マトリクス（inspect() 固定実装・矛盾症例は生成不能）
- **時間4コマ・点検は最大3回**（全点検の総当たりは構造的に不可能）。状態機械は
  newGasState/gasInspect/gasRequest として wasteLogic.ts に実装（誤依頼=残時間喪失で失敗）
| 点検先 | 薬剤切れ | 計器ドリフト | 不完全燃焼 |
| --- | --- | --- | --- |
| 薬剤タンク | **空に近い!** | 十分 | 十分 |
| 校正記録 | 済み | **期限切れ!（他計器正常）** | 問題なし |
| 炉の状態 | 安定 | 安定 | **温度低下・ムラ!** |
| 差圧 | 正常 | 正常 | **やや高** |
- アラート計器は原因に従属（薬剤切れ→HCl・不完全燃焼→CO・ドリフトのみ両方あり得る）
- 2手確定手順: 校正→（陽性ならドリフト）→タンク→（陽性なら薬剤切れ）→両陰性なら不完全燃焼
  = QA実測500/500確定。時間5コマ・点検1コマ・誤依頼は「その間に本当の原因が煙突へ達する」
  因果で失敗（内部依頼の罰でなく時間喪失の帰結）
- QA実測: 無調査ランダム依頼23.6%/炉停止パニック0%/2手トリアージ100%

### landfill_ops
- 5日・区画3×容量5・覆土材7/週・タンク容量6（超過失敗）・処理1/日・苦情3で失敗
- **覆いは持続**（さわった区画だけ夜に再覆土が必要 = 実務の作業面管理）。日課の履行が
  デフォルトで、不足時のみ優先順位判断が発生する
- **搬入は型付き（灰5〜6・不燃4前後）で、灰と不燃は別区画**（受入基準）。集約で覆い枚数は
  減るが、型ルールと容量が「どの区画をどの型に割り当てるか」の配置判断を要求する
  （無思考のばら撒きは受入不能で失敗する — QA実測でspread戦略の33%がno_space落ち）
- 天候: 雨35%/風30%/おだやか（雨1〜3晩保証・悪天候合計≤4晩の生成制約）
- 雨: むき出し区画×2 増水 / 風: むき出し区画×1 苦情（**即日覆土は飛散・におい・雨水対策**
  = research。今週は覆土材の納入遅れで全面覆土ができない設定 → 優先順位の判断が生まれる）
- 総搬入9〜10 = 集約すれば2区画で収まる設計（覆いを2枚で回せる）
- QA実測: 覆土放棄4.2%/事後対応のみ20%/散らかし配置+義務履行43.6%/**集約配置+義務履行100%**
  （配置判断そのものが成否を分ける・全300症例可解）

## 受容した簡略化（実装レビューで確認・記録）
